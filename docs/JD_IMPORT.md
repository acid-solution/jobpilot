# 招聘材料、JD 导入与分阶段分析

核对日期：2026-10-17。本文定义当前输入、状态、恢复及公开结果；术语见[词典](../GLOSSARY.md)。设计原因见[ADR](adr/0001-separate-jd-import-and-analysis.md)。

## 原始材料与候选

用户直接粘贴招聘网页文字，不必先清理导航、广告、公司介绍或人工拆岗位。每份材料最多 100,000 字符、最多 50 个候选；超限明确报错。长文本按约 8,000 字符窗口、约 1,000 字符重叠处理，成功窗口保留检查点。

识别会话与正式 JD 分开保存。模型先确认是否包含招聘职责或应聘要求，不能因小说、简历、技术文章出现技能词就生成 JD。没有岗位返回 `empty`，不创建正式 JD；技术失败保留原文和重试，不充当空结果。

单候选直接导入；多候选默认不选，用户查看标题、公司和原文后确认。编辑已有 JD 也先识别，多候选仅能选择一份更新原 ID。原始材料及未选候选仍可通过导入会话查询。

相同材料复用识别结果；已有有效记录不重复创建。未选或对应 JD 已删除的候选可再次选择。删除本身不自动重新导入。

## 接口

以下路径均位于 `/api/v1`，校验当前账号身份。新建与列表围绕当前目标，按 ID 读取、删除和重试仍检查资源属于当前账号。

| 方法与路径 | 输入与结果 |
| --- | --- |
| `POST /jd-imports` | `raw_text`、可选 `replacement_jd_id`；保存材料并启动识别 |
| `GET /jd-imports` | 当前目标最近 50 份尚未确认材料 |
| `GET /jd-imports/:id` | 状态、错误、候选原文和轮询建议 |
| `POST /jd-imports/:id/confirm` | `candidate_ids`；幂等导入并返回创建或重复的 JD ID |
| `POST /jd-imports/:id/retry` | 重试识别，按规则复用成功窗口 |
| `POST /jds`、`POST /jds/batch`、`PUT /jds/:id` | 兼容入口，统一返回导入会话 |
| `POST /jds/:id/retry` | 对正式 JD 重新进入分阶段分析 |

兼容入口不再直接写入正式 JD。Agent 添加、批量与编辑也走导入会话；候选确认仍经过业务动作确认。

## 阶段与原文

1. **提取**：基础字段、职责、技术要求、组合关系和其他条件。引用输入片段编号，由后端建立原文证据。
2. **分类**：按职责复用目录；缺项申请独立审核。缺少合法分类仍保留已提取要求。
3. **能力归一化**：精确名称/别名、目录文本召回、可选向量召回，再判断完整能力归属。
4. **相关审核和判级**：各自保留状态、失败和重试，不以技术错误代替业务拒绝。

要求保留 `single`、`any_of`、`at_least_n` 及必备/加分性质。明显复合名称先局部纠正，无合法结果不能静默删掉要求。加分证据需与技术对象处于同一语义子句，允许正常网页/PDF 折行和末尾标点。

次要岗位分类也要满足职责边界。普通 AI 调用或原型开发不能仅因缺少更合适目录就标成 Agent 应用。

能力细项保留原文、限定及范围，不独立判级、不自动成为别名。合并到同一完整能力后采用综合等级，混合关系无法等价表达时保留原要求并报告范围限制。详见[能力粒度](ABILITY_GRANULARITY_PROMPTS.md)。

## 重试与旧结果

阶段按原文哈希、提示词版本和有效租约保存。自动重试每阶段最多三次并退避；人工重试只复用仍符合当前规则的成功阶段与窗口。

技术失败只保存错误和检查点，不能覆盖上次已确认的标题、职责或有效性。页面先显示失败/处理中状态，旧能力与待审核项标明为上次结果。未完成提取不能显示“已判定无效 JD”。

当前版本在 [analysis.go](../backend/internal/jdanalysis/analysis.go)定义：
`jd-source-stages-v18` / `jd-vector-candidates-v14`。旧成功结果可带 `analysis.needs_reanalysis`，由用户主动选择按新规则分析，页面刷新不自动产生重解析费用。

## 页面与查询

进度弹窗展示真实排队和执行状态，支持后台继续与重新打开。同标签页关闭后不因轮询、切页或刷新反复提醒同一阶段；主动重试会重新显示。空结果只作提醒，不保留常驻失败卡片。

`analysis` 返回阶段状态、错误、次数、原始要求、分类依据、`has_pending` 和 `next_poll_ms`。市场页共用一次列表查询，活动任务通常约两秒轮询，并采用服务端等待建议。重新可见或聚焦时重读，旧请求不能覆盖新状态。

完成后同步更新列表、已打开详情、画像和能力清单。当前通过查询获知完成，没有新增 JD 完成推送通道。搜索和状态筛选只派生已加载列表，不产生额外网络请求。

批量加载审核、等级与阶段信息后，非空列表固定 5 次查询，空列表只有基础查询；列表和详情保留一致响应结构，不因此删字段或改变分页。
