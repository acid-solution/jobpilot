# 原始材料、岗位候选与分阶段分析分离

状态：已采纳。日期：2026-10-17。

招聘网页复制文本可能包含多个岗位及大量噪声，因此原始材料先产生候选，多候选经用户选择后才成为正式 JD。内容提取、岗位分类和能力归一化分别保存可恢复结果，模型通过原文片段编号提供依据，由服务端构造引用。

这增加了导入会话和阶段状态的维护成本，但避免了自动混合多个岗位、模型改写引用及后续服务故障导致整份结果丢失。目录审核拒绝是业务结果，技术故障必须保留并可重试，不能通过丢弃候选伪装成功。

保留 PostgreSQL 和现有 Go Worker。阶段通过同一任务租约与原文版本约束写入，独立保存成功、错误与重试次数；重试复用成功阶段。目录向量召回是可选增强，文本召回保证基本能力处理不依赖 Embedding。旧成功记录不在迁移时自动重新付费处理。
