# 能力粒度与归一化契约

核对日期：2026-10-17。本文解释现有提取、归一化与审核边界；运行时提示词以[模型适配](../backend/internal/model/deepseek)和[归一化器](../backend/internal/jdanalysis/normalizer.go)源码为准。

## 评估单位

独立能力应有可解释的内容边界和相对完整的实践、学习及评估范围。能力名称短、能编写六档等级，不足以证明它应独立评分。

- MySQL、PostgreSQL、Redis 分别评估，不合并为“数据库”。
- MySQL 索引和事务作为细项与依据，不各自给等级。
- LangChain、LangGraph 等不同框架不因同属 AI 开发就并为 Agent 开发。
- 协议理解、网络编程和服务器运维结合职责语境判断，不按 HTTP、SSH 等词固定映射。

## 三个阶段的分工

| 阶段 | 可以作出的判断 | 不能越过的边界 |
| --- | --- | --- |
| 原文提取 | 技术对象、细项、限定、要求性质和组合关系 | 不创建标准能力，不预先决定目录归属 |
| 能力归一化 | 复用标准能力、申请新增或忽略无效候选 | 不把相似度当作已确认语义 |
| 独立目录审核 | 复用、新增或业务拒绝 | 技术失败不能冒充拒绝，材料关联不自动成为公共别名 |

归一化候选附定义、包含范围、排除信号与易混淆边界。首次原文提取不塞入完整能力目录；候选缺失不能证明必须新增。

## 同义与范围归属

`equivalent` 表示含义等价，例如 Golang 与 Go；`within_scope` 表示细项属于完整能力的内容范围，例如在符合目录边界时将某项协议要求作为网络能力依据。后者不能申请为公共别名，也不能继承整项能力等级。

运行时已有决定包括 `reuse_existing`、`request_new`、`ignore`；复用对应合法能力 code，关系仅接受已实现的同义或范围归属。`needs_split`、`uncertain` 独立响应尚未实现，不能仅在文档或提示词中宣称已经支持。

## 引用与局部纠正

提取使用输入片段编号建立证据；归一化输入显式传递连续 `index`，回复和纠正沿用原编号，不让模型猜内部要求组坐标。

漏项或非法决定最多追加一次局部纠正，已经合法的项不重复生成。仍无合法结论的真实能力进入独立审核。复合名称先在提取阶段纠正，不能以清空要求掩盖失败。

加分信号只作用于同一语义子句中的技术对象；允许逐字原文中的折行和句末标点。不能让句尾“优先”扩散到整段普通要求。

## 组合与展示

原始要求结构和归一化后的综合要求分别保留。多个细项归到同一能力后保留全部细项、限定和证据；同一 JD 中同一能力的公开展示去重，不抹去不同要求组。

- 同一完整能力内的细项数量条件保留为综合判级依据，不逐细项核验。
- 不同完整能力的任选和至少 N 项继续保留。
- 混合归属后无法等价表达数量关系时保留原要求并显示限制，不能用 `min(N, 去重数量)` 伪造等价关系。
- 用户综合等级不能证明其掌握该能力的全部细项。
- 公共页面展示已确认名称；未审核项只显示数量，原始技术要求可追溯。

## 回归样例

| 输入 | 预期边界 |
| --- | --- |
| MySQL 索引、事务 | 一项能力，保留两项细节 |
| MySQL、PostgreSQL、Redis | 三项产品能力 |
| 常见协议 HTTP、SSH、SFTP 的交互流程 | 根据目录与语境归属，保留协议范围 |
| 使用 SSH 管理 Linux | 不据此断言理解网络协议原理 |
| 开发 TCP 服务端，处理连接和超时 | 对照网络编程职责 |
| UML 表达模块和交互 | 对照软件设计边界，不自动建立细项等级 |
| Go、Python、Java 至少两门 | 不同能力，保留至少两项 |
| 同一完整能力中的协议至少两项 | 综合判级，不能宣称逐协议验证 |
| 仅写 SQL 索引，无产品语境 | 不自行补写 MySQL |

当前规则与版本见 [JD 说明](JD_IMPORT.md)。合成回归通过只说明该用例受保护，真实模型仍会产生语义错误；最新安恒样本的完整验收未通过，见[评测记录](JD_PARSING_EVALUATION.md)。
