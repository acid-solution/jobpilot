# JobPilot 后台处理与一致性

现行实现核对日期：2026-10-17。总体模块见[系统架构](../ARCHITECTURE.md)，本文集中说明任务、事务与发布边界。

## 请求与组合根

[cmd/server/main.go](../backend/cmd/server/main.go)读取配置、连接 PostgreSQL、执行 Goose 迁移，然后组装 Repository、业务 Service、模型适配、Worker 和 HTTP。

HTTP Handler 将标准 `context.Context` 交给服务，身份来自认证中间件。普通账号写入在必要范围内经账号锁串行化；Agent 与跨系统导入由各自服务管理锁，避免外部网络期间持锁。

## 后台任务生命周期

提交耗时操作时，先在数据库中保存输入及任务，再向前端返回状态。消费者领取、续租、恢复和结果发布均使用持久化信息，进程内 goroutine 不承担任务是否存在的事实。

`WORKER_COUNT` 默认每类任务 2 个消费者。各队列维护独立领取 SQL、重试分类和完成事务，不能把消费者总数误当作全系统并发数。

[workerpool](../backend/internal/workerpool)统一管理循环及已领取任务的心跳、取消和退出等待。失租或续租失败取消处理；正常结束、panic 和停机都会停止并等待心跳。各业务完成写回仍必须核对租约，旧 Worker 不能凭迟到结果覆盖新执行者。

租约只证明执行权，不证明用户资料仍未变化。模型与 GitHub 请求不长期占用数据库事务；发布时重新校验业务输入。

## JD 的分阶段结果

材料识别与正式 JD 分析是两类任务。正式分析按原文版本保存提取、分类、归一化检查点，后续审核和判级独立维护。

失败写入错误与可恢复状态，不把尚未完成的有效性判断写成 `invalid`。原文未变且提示词版本允许时复用成功阶段；规则版本变化需要重新核对。当前提示词版本、重试和历史迁移语义见 [JD 处理](JD_IMPORT.md)。

阶段成功不等于最终就绪：目录审核、能力判级及用户资料都可能仍缺失。

## 统一快照与分析门槛

[readiness](../backend/internal/readiness)定义市场采集、用户画像和分析就绪。采集门槛为至少 10 份计入 JD；必要信息包含正数每周投入、期望周期及非空经历。

同一请求内复用市场、用户、必要信息和岗位要求快照，减少重复读取；快照在账号范围短事务中获取，不跨请求缓存。任选要求按不同能力计数，明确 L0 与未评估分开。

知识短板、项目推荐和学习路线复用这组规则。生成中的任务使用完整输入指纹；发布推荐另保存项目依据，避免每次等级变化都把选题等同于失效。

## 结果发布与资料版本

- 页面修改和后台结果写入推进持久化资源版本；删除仍保留版本痕迹。
- A→B→A 不是“没有变化”，旧确认仍会失效。
- 推荐与路线在最终发布事务中重新读取并检查目标、资料与版本；锁外检查不能替代最后校验。
- 新生成失败保留上一次成功结果，不用空数据覆盖；历史结果明确标记其生成依据。
- 后台批量读取 JD 的审核、等级和阶段信息，列表查询次数不随 JD 条数线性增长。

## Agent 与外部导入的不同事务

普通确认动作在同一受保护事务内核验版本、业务变更和回执；失败不能留下部分成功。

路线导入先冻结内容和幂等键，提交后再换取令牌、发送 MCP，不跨网络持有账号锁。结果不明时保留同一意图核实回执，不能回滚本地状态就断言远端未写入。详见[Agent](AGENT_DESIGN.md)、[路线](LEARNING_ROUTES.md)。

## 持久化和模型边界

数据库负责用户隔离、任务状态、版本、动作回执与已确认事实；pgvector 只辅助候选召回。能力范围归属不能自动变为公共别名，技术故障不能冒充审核拒绝。

用户 Key 由 `secure` 加密，供应商调用由用量 Transport 记账。请求已经发生但结果被丢弃仍有用量，业务事务失败不删除真实消耗。价格按返回模型名称精确匹配，见[用量说明](MODEL_USAGE.md)。

新增表或数据修复使用编号迁移，不在启动时清空重建。迁移 44 停用旧独立归一化队列；45–47 分别修正能力边界、范围召回和失败提取元数据，不自动批量付费重跑。
