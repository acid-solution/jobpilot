# JobPilot Agent 工具与确认

核对日期：2026-10-17。全站求职助手运行于 Go 服务中的 Eino，连接当前页面、求职目标和有权访问的业务资料。面试问答保留独立业务页面与会话。

## 可以做什么

助手通过业务工具读取目标、JD、画像、短板、推荐和路线，解释原文及判断依据；可以提出已有业务能力支持的修改。它不能绕过就绪门槛、账号范围、目录审核或服务校验。

结构化事实通过业务查询读取。原文检索用于解释和引用，先按账号及目标过滤；相似文本不是已确认事实。向量功能需要平台 Embedding 配置，见[开发指南](DEVELOPMENT.md)。

工具按现有服务封装，不提供任意数据库操作、通用代码执行或任意 StudyFlow Tool 转发。内部目录审核与面向用户的助手分别承担职责、使用不同凭据来源。

## 普通业务写入

1. 模型提出动作，后端保存待确认状态、资料依赖版本和内容哈希。
2. 页面显示操作及受影响内容，用户选择确认或取消。
3. 确认时在账号锁内重新读取，核验依赖、动作状态和哈希。
4. 在同一受保护事务内执行业务写入并保存回执。
5. 只有提交成功才报告结果；重复确认返回已有结果。

目标、原文、等级或其他依赖改变会使旧动作过期，包括 A→B→A。旧版动作缺少可靠版本依据时必须重新提出。模型生成的“已保存”文字不能替代真实回执。

业务操作失败时不能留下部分写入；回执本身提交失败也不能把业务写入留为成功。

## 外部路线导入

外部网络不能置于长业务事务中。路线确认事务仅冻结固定载荷、内容摘要和幂等键；提交后服务端换取短期代办令牌，调用 StudyFlow MCP。

超时可能发生在远端已经提交之后，所以状态为待核实，继续同键查询或重试。后续画像变化不改写在途内容。只有匹配回执才能显示成功；导入不自动激活计划。

工具分别支持路线查询、生成、草稿编辑、确认导入与已确认请求重试。详细边界见[学习路线](LEARNING_ROUTES.md)。

## 会话与消息

会话、消息和工具状态按账号及目标持久化。切换目标读取对应会话，不能自动跨目标混用业务材料。页面可新建、切换或删除会话；删除会话与遗忘偏好是两件事。

新会话结合页面及真实资料给出下一步建议；资料缺失时说明缺项，不编造进度。回答区分原文事实、系统判断与尚待确认的讨论。

上下文由近期完整轮次、会话摘要、已确认偏好和版本化业务观察组成。预算、遗忘纪元与迟到结果保护见[上下文与记忆](AGENT_CONTEXT_MEMORY.md)，该文档为此项规则的唯一详细入口。

## 问答与等级

初始评估用于建立起始等级；能力验证只验证下一档，成功建议经用户确认后写回；复习允许解释但不改等级。一次会话围绕完整能力综合判断，不产生每个细项的独立等级。

全站助手可以解释问答页面，但正式作答、追问、提交与确认仍使用问答业务接口，不能通过聊天绕过验证规则。

## 失败与核验

模型失败、无权限、资料过期、失租、取消和技术故障分别展示。调用已经发生时仍可能产生用量，见[模型用量](MODEL_USAGE.md)。

核验应覆盖重复确认、过期确认、提交失败、跨账号/目标、遗忘后的迟到响应，以及外部导入响应丢失。测试入口见[验证指南](VALIDATION.md)，实际问答和工具选择质量需另做真实样本评测。
