## 样本与方法

47 段是明确标注的合成测试材料，另有两份官网短摘录配合合成网页杂项，以及一份用户授权截图转录。这不是 50 份真实 BOSS 或官网整页抓取，因此不能据此推断线上所有招聘网页的总体成功率。

覆盖普通岗位、网页导航和广告、重复噪声、Markdown、断行、缺名称或公司、长文尾部岗位、要求组合、多岗位、原文提示注入。负例包括小说、包含程序员和技能词的小说、简历、技术教程、新闻、公司介绍、导航、购物、诗歌、聊天、职位名称列表、日志、学习计划和随机文字。

每份材料依次运行实际识别、提取、岗位分类和无 Embedding 的能力归一化。检查候选数量、有效提取、合法分类、归一化状态；逐项检查要求组和选项引用可定位原始测试材料。关键技术要求使用预先定义的名称及少量中英文等价表述计数，属于固定标签召回指标，并非人工逐句评估全部职责和要求。

## 持久化、审核与判级

另用语料中五段执行真实 PostgreSQL 与全部 Go Worker，并有意只提供后端岗位目录来触发目录缺项。多候选确认、正式 JD 保存、独立新增分类审核、能力审核、判级和市场画像统计均通过。结果：5 份正式 JD，1 份计入目标，4 项目标能力；2 份分类审核、7 份能力审核、1 份判级完成。31 次调用，72,866 输入 token、7,077 输出 token；测试整体 29.73 秒，Worker 处理阶段 24.031 秒。

早期三段测试曾遇到模型 HTTP 400；扩大测试后又遇到能力审核 JSON 连续不合法而耗尽重试。技术故障均保留为待重试错误，没有当作业务拒绝。审核器加入一次结构纠正后，五段全链路通过；没有撤销或减少测试中的有效技术要求。

基础语料指标不包含为全部 35 段执行目录新增审核和判级的完成率。新增分类审核另在端到端用例中核验。
