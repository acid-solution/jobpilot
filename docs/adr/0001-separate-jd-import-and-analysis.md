# 原始材料、岗位候选与分阶段分析分离

状态：已采纳。决策日期：2026-10-17。

招聘网页可能包含多岗位和噪声，直接把整份文本写为一份 JD 容易混合岗位。保留原始材料识别会话，先产生候选，单候选直接导入、多候选由用户选择，再进入正式 JD 分析；提取、分类与归一化分别保存可恢复结果，引用由原文片段编号在后端构造。

这增加会话、阶段和版本管理的成本，但让用户能够核对岗位边界，并在后续模型或目录服务失败时保留前阶段成果。继续使用 PostgreSQL 与既有 Go Worker，阶段写入受同一任务租约及原文版本保护，目录向量为可选增强。

技术故障只记录失败，不能覆盖既有业务事实或冒充审核拒绝；旧结果需要按新规则分析时由用户主动触发，不通过迁移自动付费重跑。当前协议与恢复边界见[JD 处理](../JD_IMPORT.md)。
