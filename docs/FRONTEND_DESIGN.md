# JobPilot 前端设计

核心业务原型第一轮完成 · 2026 年 9 月 12 日

这份文档把[需求文档](REBUILD_PRD.md)和[页面流程与验收说明](REBUILD_FLOWS_AND_ACCEPTANCE.md)转成可以制作原型和开发页面的前端方案。已经确定的业务规则直接采用；页面布局、交互方式和视觉风格仍按重要程度逐项确认。

## 前端要让用户看懂什么

用户进入 JobPilot 后，应该随时知道三件事：当前在准备哪个求职目标、两类画像完成到哪里、下一步应该做什么。页面还需要让用户查到每个判断的来源，避免只看到模型生成的结论。

前端主要承担：

- 引导用户完成市场画像和用户画像。
- 展示后台分析的处理中、成功、失败和待更新状态。
- 展示 JD 原文、分类、能力要求和用户能力等级之间的依据关系。
- 在画像完成后展示项目推荐和知识短板。
- 提供全站求职 Agent 入口，并展示工具操作确认和执行结果。
- 管理用户账号与模型配置。

## 当前页面范围

| 页面或界面 | 首版职责 |
| --- | --- |
| 注册、登录、找回密码 | 支持邮箱验证、密码登录和密码重置 |
| 工作台 | 展示当前目标、两类画像进度、具体缺项和下一步入口 |

项目推荐页面已经覆盖入口、门槛、结果比较、详情、选择项目和已选项目状态。候选项目来源与筛选机制确定后，再用真实推荐结果验证内容质量。

## 技术方案（已确认）

首版前端使用 React、TypeScript 和 Vite。第一阶段不引入组件库，先用项目内组件和样式实现已经确认的工作台、全局框架与悬浮 Agent，避免在其余页面尚未定稿时过早固定组件体系。

第一阶段使用本地模拟数据展示完整交互，Agent 会话暂存在浏览器 `localStorage`。这些数据仅用于验证页面和交互，不代表后端接口或最终数据结构；账号、画像、后台任务和模型调用将在对应设计确定后接入。

## 视觉风格（已确认）

正式前端沿用此前确认的悬浮 Agent 原型风格：使用蓝灰色主色、浅灰页面背景、白色内容面板、轻量边框和克制阴影；文字层级与页面间距保持紧凑，避免过大的标题、装饰性渐变和厚重卡片。导航、画像状态和 Agent 操作统一使用 Lucide 线性图标。

## 登录后的整体结构（已确认）

首版前端以 2026 年 9 月 11 日确认的工作台原型作为基准，采用以下总体结构：

- 桌面端左侧为稳定主导航，放工作台、市场画像、用户画像、项目推荐、知识短板和设置。
- 顶部固定展示当前求职目标，并提供切换入口，让所有页面明确自己正在使用哪组资料。
- 中间是当前页面的主要内容，优先突出进度、缺项、依据和下一步操作。
- Agent 的展示方式已经确定为悬浮助手。收起时在页面边缘显示小助手入口，展开后成为覆盖在当前页面上方的浮动窗口，不固定占用业务页面宽度。
- 浮动窗口提供收起、重新打开、查看会话列表、新建对话、切换对话和删除对话的入口。删除前显示确认。
- 窄屏浏览器将主导航收起，Agent 展开时使用接近全屏的覆盖层，保证消息和确认内容可读。

工作台当前先采用原型中展示的页面：顶部显示当前求职目标，主体展示市场画像和用户画像的完成进度、具体缺项与下一步操作，页面右下方提供可拖动、可收起的悬浮 Agent。后续可以调整文案和细节，但不随意改变这套页面骨架。

市场画像、用户画像、项目推荐、知识短板和设置页面继续沿用相同的全局框架，再分别确认各自的内容区域。

## 全局交互规则

- 每个页面只保留一个最主要的下一步操作，次要操作降低视觉权重。
- “未完成”必须说明具体缺什么，例如还差 2 份 JD、Redis 尚未评估，不能只显示一个百分比。
- 后台任务在原位置显示状态；用户离开页面再回来时，仍能看到任务结果或失败原因。
- 已有结果重新生成时继续展示；只有新结果成功且依据仍为最新时才替换。
- 事实、系统判断和信息不足使用不同文案，并提供原始依据入口。
- 空白、首次使用、处理中、失败、无权限、资料已变化和模型未配置都需要专门状态。
- Agent 发起持久化操作时，在浮动窗口内展示操作摘要和确认按钮；没有确认就不改变页面数据。

## 工作台初稿

工作台不堆无关统计，主要展示：

1. 当前求职目标与切换入口。
2. 市场画像进度，包括已计入 JD、处理中 JD 和还差多少份。
3. 用户画像进度，包括必要资料和待评估能力。
4. 一个根据当前状态生成的主要下一步操作。
5. 项目推荐和知识短板入口；画像未完成时说明解锁条件。
6. 最近正在执行或失败的必要任务提示。

## 市场画像页面初稿

页面包含 JD 录入入口、JD 列表、岗位能力汇总三个主要区域。

JD 列表至少显示岗位名称或用户可识别的标题、处理状态、主次分类、是否计入当前目标。打开详情后显示完整原文、分类依据、能力要求、学历与年限条件，以及失败重试入口。

岗位能力汇总直接显示标准能力名称，不在名称前添加图标或字母占位。每项显示该能力能够满足多少份已计入的 JD，并保留查看原文依据的入口。这里的“可满足”只说明能力对岗位要求的覆盖范围，不读取用户画像，也不表示用户已经掌握。页面不展示要求组名称、`single/any_of/at_least_n` 或“明确指定/可选能力”等解析概念。MySQL 等完整能力始终只展示一个综合能力项。

## 用户画像页面初稿

页面按个人情况、材料和岗位相关能力组织。用户可以粘贴经历、上传文字版 PDF 或 DOCX，检查解析文本后再用于分析。

能力列表显示能力名称、当前综合等级、信息来源和状态。待评估能力提供补充问答与自行设置两个入口；已有充分材料的能力不重复要求答题。当前目标无关的已评估能力默认不展示，但数据仍保留。

## 项目推荐与知识短板初稿

两类画像未完成时，页面直接说明阻塞条件并提供补齐入口。生成中和生成失败时保留之前的当前结果。

知识短板分为“短板总览”和“面试问答”两个页面。短板总览按完整能力项展示当前等级、市场画像等级、差距和判断依据。页面同时保留未解锁状态和结果状态，明确“待评估”不能作为能力不足，并提供进入两类画像的补齐操作。结果页先汇总需要补强、达到目标和要求不明确的能力数量，再用列表展示需要补强的完整能力项；点击后在右侧抽屉查看用户当前能做到什么、市场建议达到什么程度，以及双方依据。MySQL 等能力不拆成内部知识点分数，结果也不能根据综合等级猜测具体薄弱知识点。

面试问答页先让用户选择“能力验证”或“复习练习”，再选择要练习的完整能力项。能力验证采用闭卷问答，作答过程中不显示提示和参考答案，Agent 可以根据回答继续追问；复习练习可以显示提示、参考答案和讲解，且不改变能力等级。问题可以覆盖一项能力中的不同知识内容，但页面只展示这项能力的综合等级，不生成内部知识点分数。

能力验证页明确展示当前等级和本轮唯一目标，例如“当前 L2，本轮验证 L3”。一轮包含 6 道核心题，最多出现 3 道用于澄清或补证的追问；页面分别显示核心题进度和追问数量，追问不作为额外加分题。通过后只建议上升一级，经用户确认后更新画像，未通过则保持原等级。页面不提供跳级或降级结果，具体通过标准尚待确认。

项目推荐页同时保留未解锁状态和结果状态。结果采用摘要卡片列表加右侧详情抽屉：首页用于比较最多 3 个项目，摘要显示项目类型、用途、主要推荐理由、能力方向和预计范围；详情说明项目面向谁、解决什么问题、为什么适合用户、用户需要承担的主体工作、能够体现的能力，并区分画像中的已知条件与开始前仍需验证的设想。用户在详情中选择项目后进入独立的“已选项目”状态，集中查看项目定义、主体范围、推荐理由、能力对应关系和待验证事项，并可以返回推荐列表更换选择。重新推荐时允许选填调整意见，明确本次意见不写入用户画像，并在新结果成功前保留当前结果。

## 设置页面初稿

页面让用户从 DeepSeek、Qwen、GLM、Kimi 中选择已经支持的服务和模型，填写必要配置并测试连接。已保存的 Key 只显示遮盖结果，提供替换和删除入口。首版不显示通用协议类型和任意 Base URL。

## 悬浮 Agent 助手初稿

展开后的浮动窗口至少包含当前上下文提示、当前会话标题、对话消息、引用依据、工具执行状态、操作确认区域和输入框。用户应该能看出助手正在针对哪个求职目标和哪个页面回答。

用户新建对话时，助手不展示固定欢迎语。程序根据当前求职目标、所在页面和画像完成度，主动生成一条“下一步建议”，说明现在最应该补充什么以及后续顺序。首版先由确定性规则生成，接入后端后改用真实画像状态作为输入。

窗口可以收起成页面边缘的小助手。重新打开时恢复当前对话和未完成的输入。桌面端允许用户移动浮窗位置；窄屏端不要求自由拖动，优先保证内容完整显示。

会话列表提供新建、切换和删除入口。新建对话后原对话继续保存；删除按钮需要先显示会话名称和确认提示。删除后的恢复方式留到后续讨论。每个对话绑定创建时的求职目标，切换目标时显示对应目标下的对话。

助手提出保存或修改时，确认区域需要说明准备执行什么、会影响哪些资料，并提供确认和取消。执行失败时保留用户消息与操作内容，说明失败原因并允许合理重试。

同一对话不自动混用多个求职目标的资料；跨目标比较以后作为明确功能单独设计。

## 当前实现范围与接下来逐项确认

登录后的核心业务页面已经完成第一轮原型，包括工作台、市场画像、用户画像、项目推荐列表与已选项目页面、知识短板总览、面试问答、全局导航、当前求职目标，以及可收起、移动、新建对话、切换对话和删除对话的 Agent 浮窗。面试问答已经包含能力验证与复习练习两种模式、能力选择和逐题作答界面；能力验证的通过标准尚未确定，因此原型不生成升级结论。

当前页面使用模拟数据验证布局与交互，尚未连接后端；题目生成、追问和能力判断也仍是原型流程。核心业务页面的结构与视觉先按当前版本收口。登录注册、设置页面和真实接口状态在账号、模型与后端接口进入实现时补齐；加载、失败、资料变化等状态随对应接口一起完善，不再因此重新调整整套页面骨架。
