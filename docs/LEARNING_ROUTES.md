# 学习路线与 StudyFlow 导入

JobPilot 负责规划，StudyFlow 负责执行。侧边导航提供独立的“学习路线”页面，页面和全局 Agent 使用相同服务。推荐本身仍只提供选题与仓库比较，不因选择项目而自动开始规划。

## 使用流程

1. 完成两类画像、审核及判级，并选择或重新核对项目。
   学习路线页先展示准备清单和对应页面入口；条件未齐时不显示预算表或生成按钮。已经生成的路线保留为只读预览。生成条件读取失败时暂停生成和新导入，可重新检查；后端同样校验前置条件，不能绕过页面直接创建任务。
2. 分别填写项目实践与知识准备的周预算，两者合计不超过画像每周总投入；沿用画像期望周期。各自选择课时或日期模式，日期只到天。
3. 生成两份并行计划。阶段有成果，任务有行动、分钟数和完成标准；任选要求只选择足够路径。没有必备差距时安排复习与验证。
4. 编辑预览并保存。后端检查版本、阶段任务数量、周期与预算。手动改变前置顺序会提示，不限制任务推进。预算不足不自动延长周期。
5. 确认固定内容，导入 StudyFlow 草稿并查看回执。首次新建目标和两份计划，后续仅为实际变化的计划新增草稿。已有草稿需在 StudyFlow 激活或取消。
6. 等级变化自动刷新知识准备摘要，不调用模型、不改变项目。点击“更新知识计划”才重新生成知识任务，项目计划保持原样。新草稿还需再次确认导入与激活。

任务完成不等于能力升级。能力等级沿用设置、材料评估与正式验证流程。

## 服务端配置

先部署 shared-auth 的令牌交换与 StudyFlow MCP 导入扩展，并完成数据库迁移，再开启 JobPilot 的 `LEARNING_ROUTES_ENABLED=true`。Worker 数复用 `WORKER_COUNT`，默认 2。

导入配置：`AUTH_EXCHANGE_URL` 指向 `/auth/v1/token/exchange`；`STUDYFLOW_MCP_URL` 与另外两个服务的 `STUDYFLOW_MCP_RESOURCE` 完全相同；`JOBPILOT_EXCHANGE_SECRET` 与 shared-auth 相同，至少 32 字符；`STUDYFLOW_WEB_URL` 是正常登录后的网页地址。生产使用 HTTPS，本地仅允许回环 HTTP。三项导入配置都为空时，可以只启用规划。

路线生成使用用户 DeepSeek 配置。代办令牌只在服务器之间传输，绑定固定导入键、内容摘要和 MCP 受众，最多两分钟且不超过来源访问令牌期限；不进入模型、前端、日志或路线存储。普通 StudyFlow API 不接受代办令牌，不提供浏览器单点登录。

路线模型接入必须实现带输出上限的结构化生成接口，当前请求上限为 8,000 个输出 token，不再回退为普通生成调用。共享续租执行器管理处理期间的心跳和退出，任务自己的发布校验、失败重试和导入事务保持独立。

## 状态与一致性

- 生成任务持久化，使用租约、心跳和过期恢复，发布前在账号事务锁内检查目标、完整输入及路线版本；失败保留旧路线。
- 生成中的任务继续使用完整输入指纹；已发布推荐使用独立项目依据指纹，等级变化不使选题过期。历史依据只从对应成功任务回填；不能恢复的信息不冒充当前画像。
- 岗位要求集合、经历或时间发生变化后，可重新生成推荐，也可核对原项目并重新选择，保存这次核对的依据。旧推荐中的依据仍标为“生成时依据”。
- 导入确认先冻结载荷与幂等键，在提交后调用 MCP，网络期间不占用账号锁。后续画像变化不改写在途载荷。
- 超时或断线显示待核实，同键重试；只有匹配的真实回执才显示成功。每份执行计划保留独立版本和原进度。
- 已导入路线的编辑创建新路线版本；未导入草案以修订号防止并发覆盖。待核实内容不能被悄悄编辑。

接口：读取 `/api/v1/learning-route`、生成 `/generate`、编辑 `/draft`、确认 `/import`，以及 `/imports/:id/retry`。返回包含就绪状态、实时知识摘要、生成状态、当前版本、重排提示和导入回执。

不自动激活，不自动完成，不自动升级，也不根据执行进度持续调用模型重规划。
