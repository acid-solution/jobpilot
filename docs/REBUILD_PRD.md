# JobPilot 产品与使用说明

现行版本：2026-10-17。本文描述当前产品范围。业务术语见[词典](../GLOSSARY.md)，页面验收见[验收清单](REBUILD_FLOWS_AND_ACCEPTANCE.md)。

## 面向谁、解决什么

面向已有编程基础、正在准备开发岗位的求职者。用户提供真实岗位和个人经历，了解当前要求与自身能力之间的差距，选择可投入的项目，再主动生成学习安排。

产品输出是有依据的辅助判断，不能证明用户已经具备某项能力、项目已经完成或必然通过招聘。市场画像代表当前收集样本，不代表整个就业市场。

## 用户完成的主流程

1. 注册登录，选择岗位方向、求职类型及适用届别。
2. 配置自己的 DeepSeek 凭据，提交相关招聘材料。
3. 核对识别出的岗位，确认导入，查看各阶段处理与原文依据。
4. 补充个人必要信息、简历或经历，确认材料分析并补足待评估能力。
5. 查看知识短板，按需进行正式验证或复习。
6. 生成项目推荐，比较项目设想和 GitHub 参考，主动选择当前项目。
7. 在独立学习路线页设置两类预算，生成、编辑并确认导入。
8. 到 StudyFlow 正常登录，核对草稿后主动激活执行。

## 求职目标与岗位材料

一个账号同一时间围绕当前求职目标操作。目标可以包含多个岗位方向；复合目标不拆成多份独立画像。岗位分类依据实际职责，不能只依据标题或技术关键词。

材料允许带网页杂讯和多个岗位。识别未发现有效招聘内容时显示空结果；技术失败保留原文和重试。单候选直接导入；多候选默认不选，用户核对原文后确认。编辑已有 JD 保留原记录身份，多候选只能选一份替换。

JD 分别展示有效性、目标关系和处理状态。有效但不相关属于正常筛选结果。原文、要求组合、细项及错误仍可追溯。材料识别、重试和删除后的再次导入见 [JD 专项](JD_IMPORT.md)。

## 市场画像与能力

当前目标至少有 **10 份计入画像的 JD** 才达到采集门槛，10 份不是上限。采集完成与审核、判级完成分别判断。

能力以完整技术对象评估，例如 MySQL 是一项能力，索引和事务是其细项。归一化区分同义别名、内容范围归属和仅仅相关。不同产品或框架不因同属一个领域就合并。

岗位要求保留单项、任选、至少 N 项及加分性质。只需选择足够的满足路径；不能把任选要求的全部候选当成必备短板。市场常见等级按相关要求分布统计，并列时建议准备等级取其中较高档，加分要求单列。

公共能力列表展示已确认标准名称，未审核候选只显示数量。原始技术要求可以查看，但不能冒充已确认目录。

## 用户画像与就绪条件

必要信息包括开发经历、每周投入与期望周期。用户提供的材料先核对文字，再确认分析；文件解析限制见[开发指南](DEVELOPMENT.md)。

能力来自材料支持、补充问答或用户自行设置。明确 L0 与未评估不同。完成用户画像意味着信息足以判断，不意味着全部能力达标；已满足的组合要求无需评完其余候选。

生成知识短板、项目推荐和新路线还需相关目录审核、岗位判级就绪。页面解释缺失条件并提供入口，后端执行相同校验。关闭平台审核或缺凭据可能造成等待，不能显示虚假成功。

## 知识短板与问答

短板按完整能力或整条组合要求表达，并提供用户与市场依据。单个综合等级不能精确诊断所有具体知识点。

- 初始评估：没有当前等级时建立起始水平。
- 能力验证：以已有等级的下一档为目标，通过后由用户确认提升一级。
- 复习练习：允许提示、答案与解释，不更改能力等级。

问答与 Agent 使用各自的业务会话。页面恢复要读真实会话状态，失败或终止不能冒充验证完成。

## 项目推荐

推荐先根据画像提出项目设想，再检索核查 GitHub 仓库作为对照。输出最多三项，可说明适用场景、主体工作、技术侧重、成本、差异和仍待验证的条件。参考仓库不是必选二开对象；缺少合适参考时明确说明，不编造仓库。

用户主动选择项目。重新生成时可输入本次调整意见；失败保留旧结果。资料变化后分别判断推荐内容与选择依据是否需要核对。等级变化可以更新知识摘要，不自动替用户更换选题。

## 学习路线与助手

路线包含项目实践与知识准备两份并行计划，各自设置日期或课时模式，预算合计不超过个人每周总投入。日期只到天，任务前置关系用于说明，不形成跨计划执行锁。

用户主动生成、编辑、确认固定内容，再导入 StudyFlow 草稿。首次创建目标和两份计划，后续只给变化的计划新增草稿；已有草稿需要先激活或取消。导入、激活、任务完成和能力升级是不同操作，见[路线说明](LEARNING_ROUTES.md)。

右下角 Agent 可以查询资料、解释结果并提出受控动作。持久化业务修改需要逐次确认，资料变化后旧确认可能失效。长期偏好先确认保存；聊天讨论和摘要不能替代正式业务事实。见[工具与确认](AGENT_DESIGN.md)、[上下文与记忆](AGENT_CONTEXT_MEMORY.md)。

## 当前支持与限制

| 范围 | 当前边界 |
| --- | --- |
| 生成模型 | DeepSeek；四家模型适配不是当前功能 |
| 向量化 | 可选百炼平台配置，用于候选召回和原文检索 |
| 外部项目参考 | GitHub API，受凭据、限流与网络影响 |
| 身份 | shared-auth 共用账号、两个网站分别登录 |
| 规划执行 | JobPilot 规划，StudyFlow 执行，功能开关控制接入 |
| 模型费用 | 记录调用及估算，不提供供应商真实结算账单 |
| 产品质量 | 需按真实样本评测，不能以单元测试替代 |
| 后续方向 | 更多模型、更多浏览器端到端覆盖按需求评估，不作为现有承诺 |

运行条件见[开发指南](DEVELOPMENT.md)，特定样本和已知失败见[验证指南](VALIDATION.md)。
